# Code repository for SAE4LMIC Dashboard 

This code repository contains codes needed to generate the input to the website at [https://sae4lmic.stat.uw.edu/](https://sae4lmic.stat.uw.edu/). 

To re-create the website locally, you will need the following
1. The data structure described in the next section. 
2. The codes in this repository to generate static and interactive plots, as well as reports. 
3. The codes in the [website repository](https://github.com/UW-Statistics/gatesweb) to deploy the website (locally or through Github Action)
4. Optionally, for websites with many large HTML files, you may need to store the source files in more than one repository to allow Github Action to properly build the website. See the [webplots folder](webplots/) for details.

## Requirements

The code depends on the **up-to-date development versions** of `SUMMER` and
`surveyPrev` from GitHub. Install them with:

```r
# install.packages("remotes")   # if needed
remotes::install_github("richardli/SUMMER")
remotes::install_github("richardli/surveyPrev")
```

> **Important:** the CRAN release of `surveyPrev` (e.g. 1.0.0) is **not
> sufficient** — the prep and modeling scripts use functions that only exist in
> the GitHub development version (`get_geoBoundaries`, `addUpper`, `datainfo`).
> Because `library(surveyPrev)` silently loads whichever copy is first on
> `.libPaths()`, make sure the GitHub version is the one that gets loaded (an
> older CRAN copy in your user library can shadow a newer system install).

## Repository structure

This code repository assumes the following directory structures

- `Gates-data`
  - `rawDHS` Raw DHS recode data
  - `geoBoundaries` admin shapefiles
- `Gates-results`
  - `results` fitted model results
  - `reports` PDF reports on the website
  - `estimates` CSV of final estimates on the website
  - `ReportPlots` static plots for the report
  - `ShinyPlots1` First batch of HTML plots to be passed to website 
  - `ShinyPlots2` Second batch of HTML plots to be passed to website 
  - `StaticWebPlots` Static plots to be passed to website 
- `SAE4LMIC` **(This repository)**
  - `info` Meta data and list of surveys
  - `prep` R scripts to prepare datasets
  - `report` RMD files for generating reports
  - `models` R scripts to fit the final models on the website
  - `check` R scripts to check estimates against the DHS API (national)
  - `plots` R scripts to generate files in `../Gates-results/ReportPlots
  - `webplots` R scripts to generate files in `../Gates-results/ShinyPlots`
  - `misc` additional R scripts to diagnose, evaluate, or compare models
  - `document` generated documentation (e.g. the workflow doc)


## Metadata files (`info/`)

The CSVs in `info/` drive the whole pipeline. How each one is produced:

| File | How it is made |
|------|----------------|
| `infolist.csv` | **Manually maintained.** One row per indicator (`ID, Description, Full_definition, recode, direction, Chapter, API, Group`). Edit it when adding or changing an indicator. Read by nearly every script. |
| `surveyslist.csv` | **Manually maintained.** One row per survey / country-year (`country, year, country_short, survey_name, upper_name, lower_name, iso3`). Edit it when adding a new survey. |
| `shapefileList.csv` | **Generated by code** — written at the end of `prep/prepare_basic.R`. One row per survey (`survey_name, country, year, n_admin1, n_admin2, n_geo_cluster, n_cluster, shapefile`); the admin/cluster counts are read from each survey's `basic.Rdata` and `shapefile` records the boundary source (geoboundaries / GADM / WHO). No need to hand-edit — rerun `prepare_basic.R`. The incremental block at the end of that script updates only the selected survey's row (so it will not overwrite rows for countries without a local `basic.Rdata`). |
| `infolist_enriched.csv` | **Manually maintained; not used by the pipeline.** An extended `infolist` with extra columns (`Denominator, Measurement_Type, Population_base, WorldPop_raster, Denominator_used`). Currently not read by any script — reference only. |
| `result_prefix_tracker.csv` | **Tracking table (regenerable).** Per-survey record of which core script produced the results and the resulting file prefix — `model-core.R` → prefix `NA` (`res_adm0-`), `model-core-newvarfix.R` → prefix `new_` (`new_res_adm0-`). Columns: `country, year, survey_name, core_script, prefix, completion_date` (`completion_date` = the result files' modification date; empty when results aren't stored locally / not yet fit). Both prefixes are read transparently via `misc/resolve_qs.R`; update the row when a survey is re-fit. |
